**Laufzeit-Override-Semantik (G1-Kernpunkt):** Kein CLI-Flag schreibt die
persistierten Einstellungen. `--debug` überschreibt nur die im Setup verwendete
Kopie (`lib.rs:528-532`), `--start-hidden` wird per ODER mit der Einstellung
kombiniert (`lib.rs:577`) und `--no-tray` wird pro Start aus dem verwalteten
`CliArgs`-Zustand gelesen (`lib.rs:570`, `lib.rs:598`). Die
Fernsteuerungs-Flags `--toggle-transcription`/`--toggle-post-process`/`--cancel`
werden im Erstprozess **gar nicht** aus `cli_args` gelesen — grep-verifiziert:
`cli_args` wird in `lib.rs` nur an den Stellen 355 (Headless-Erkennung), 447
(Verwaltung), 473 (Headless-Args), 529 (`--debug`), 570/582 (`--no-tray`) und
577 (`--start-hidden`) verwendet; die drei Fernsteuerungs-Flags kommen dort
nicht vor.

## 3. Single-Instance-Weiterleitungspfad (G2)

Implementierter Pfad, vollständig in `src-tauri/src/lib.rs`:

1. **Headless-Ausnahme:** Ist eines von `--transcribe-file`, `--list-devices`,
   `--list-models` gesetzt, gilt `headless_mode = true`
   (`lib.rs:354-355`). Dann wird das Single-Instance-Plugin **nicht**
   registriert (`lib.rs:419`, `if !headless_mode`), damit ein zweiter Aufruf
   nicht als stummer No-op an die laufende App weitergeleitet wird, sondern
   eigenständig läuft (`lib.rs:414-418`, Kommentar).
2. **Plugin-Registrierung:** Andernfalls registriert
   `tauri_plugin_single_instance::init` einen Callback (`lib.rs:420-430`).
   Startet ein zweiter Prozess, reicht das Plugin dessen Argumentliste (`args`)
   an diesen Callback der **laufenden** Instanz; der zweite Prozess beendet
   sich (Plugin-Vertrag, dokumentiert in `AGENTS.md`, Abschnitt „Single
   Instance Architecture“ und „CLI Parameters“).
3. **Argument-Matching:** Der Callback prüft die weitergeleiteten Argumente als
   exakte String-Vergleiche in fester Reihenfolge (`lib.rs:421-426`):
   `--toggle-transcription` → `signal_handle::send_transcription_input(app,
"transcribe", "CLI")`; sonst `--toggle-post-process` → Binding
   `transcribe_with_post_process`; sonst `--cancel` →
   `utils::cancel_current_operation`; **sonst** (kein Flag) →
   `utils::show_main_window(app)` (`lib.rs:427-429`). Bei mehreren Flags in
   einem Aufruf gewinnt der erste Treffer der Kette (else-if).
4. **Gemeinsame Ausführungslogik:** `send_transcription_input`
   (`signal_handle.rs:18-24`) ruft
   `TranscriptionCoordinator::send_input(binding_id, source, is_pressed=true,
push_to_talk=false)` — derselbe Einstiegspunkt, den auch die
   Unix-Signalhandler nutzen (SIGUSR1/SIGUSR2, `signal_handle.rs:26-57`; auf
   Linux wird SIGUSR1 bewusst nicht behandelt, da er WebKitGTKs GC gehört,
   `signal_handle.rs:29-33`, Issue #1660).
5. **Coordinator-Semantik:** `push_to_talk=false` erzwingt Toggle-Verhalten
   (`transcription_coordinator.rs:54-56`, Passthrough; Toggle-Zweig
   `transcription_coordinator.rs:177-189`): Idle → Start, laufende Aufnahme
   desselben Bindings → Stop, **während `Processing` → ignoriert**
   (`transcription_coordinator.rs:185-187`, Debug-Zeile „Ignoring press …
   pipeline busy“).

## 5. Diagnose-Schnellpfad (Reihenfolge)

1. Klären, welcher Pfad gemeint ist: Kaltstart (Abschnitt 2, Laufzeit-Flags)
   oder Fernsteuerung einer laufenden Instanz (Abschnitt 3). Fernsteuerungs-Flags
   ohne laufende Instanz sind per Design No-ops (R13).
2. `--debug` beim **Kaltstart** setzen (Abschnitt 2) und reproduzieren.
3. Shortcut-Frage: Welches Backend? Log nach `tauri global-shortcut event`
   (`tauri_impl.rs:114-117`) vs. `handy-keys event` (`handy_keys.rs:130-133`)
   durchsuchen; fehlen beide, war nichts registriert (R1, R4, R5, R7).
4. Fernsteuerungs-Frage: exakte Flag-Schreibweise, genau ein Flag pro Aufruf,
   Coordinator-Stadium beachten (R14, R15).
5. Fenster/Tray-Fragen entlang R17–R20 prüfen (`lib.rs:569-585`, `589-609`).
